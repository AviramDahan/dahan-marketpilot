# Phase 10.1 Research: Runtime Orchestrator for Strategy-to-Paper E2E Flow

**Researched:** 2026-06-15  
**Domain:** QuantConnect LEAN runtime integration, paper-only strategy orchestration, Object Store/dashboard export  
**Confidence:** HIGH for codebase contracts and official QuantConnect documentation points; MEDIUM for final QC runtime details until implemented against real QC credentials.

## Summary

Phase 10.1 should close the milestone audit gap by adding a thin runtime orchestrator and LEAN bridge around existing MarketPilot domain contracts, not by rewriting setup, scoring, risk, Paper mode, Telegram, or dashboard logic.

The safe architecture maps QuantConnect-authoritative data into existing side-effect-free MarketPilot inputs, evaluates setup evidence, scores/ranks candidates, applies Paper mode and reconciliation gates, then emits either shadow evidence, paper-only order intents, or gated QuantConnect Paper orders.

Primary recommendation: build a pure `marketpilot.runtime_orchestrator` service, keep `lean/main.py` as a thin QuantConnect adapter, and use QuantConnect Object Store or approved read API paths for dashboard export evidence.

## Existing Patterns To Reuse

- Central fail-closed safety already exists via `PAPER_TRADING_ONLY`, `validate_safety_config`, and per-config `paper_trading_only: true` checks.
- Setup modules are side-effect-free: they return `SetupResult`, `NumericEvidence`, `SetupTiming`, and rejection reasons, not orders.
- `StrategyMode`, `BarTimeframe`, completed-bar metadata, partial-session flags, and timeframe allowance checks already exist.
- Scoring/ranking already produces `MarketPilotScore` and exactly one `RankedCandidate` per symbol.
- Risk/order lifecycle are separated: `evaluate_portfolio_risk()` returns a `RiskDecision`; `OrderIntent` is an audit intent shape, not a submission object.
- Paper mode gates are explicit: only `approved_for_limited_paper` and `approved_for_full_paper` can be paper-order eligible.
- QuantConnect reconciliation treats QC snapshots as authoritative and blocks new entries on mismatches while preserving exits.
- Telegram is transport-neutral and safety-independent.
- Dashboard has read-only endpoint allowlists and Object Store export key names, but currently only loads `none` or `local_json`.
- `lean/main.py` is still a minimal SPY/QQQ shell and does not call MarketPilot runtime modules.

## Official QuantConnect Grounding

- Object Store is organization-specific key-value storage usable from backtests, research, and live algorithms for strings, JSON, XML, and bytes. This supports dashboard JSON evidence export after implementation verifies exact runtime calls.
- QuantConnect Algorithm Framework documents the separation of universe selection, alpha insights, portfolio construction, risk, and execution. Phase 10.1 should preserve this separation while keeping project risk sizing authoritative.
- Universe selection changes are surfaced through `OnSecuritiesChanged` / `on_securities_changed`; use this for SymbolData lifecycle cleanup.
- Time-period consolidator handlers receive consolidated bars when bars close based on exchange timezone; use this to enforce completed-bar and partial-session contracts.
- QuantConnect Cloud API includes Live Management and Object Store Management, supporting a read-only dashboard fetch path after endpoint verification.

## Safe Architecture Recommendation

```text
QuantConnect subscriptions / universe
  -> on_securities_changed cleanup + symbol registry
  -> daily / 4H / optional 1H completed-bar adapters
  -> UniverseCandidate + SymbolData + IndicatorResult + RegimeResult
  -> setup registry: Trend Pullback / Volume Breakout / Relative Strength
  -> score_setup_result()
  -> rank_candidates()
  -> reconciliation gate + paper mode gate
  -> evaluate_portfolio_risk()
  -> OrderIntent + lifecycle audit
  -> gated QuantConnect Paper execution only when explicitly eligible
  -> NotificationDomainEvent emission
  -> Object Store dashboard JSON export
  -> read-only dashboard fetch/cache/stale warning
```

## In Scope

- Add a pure runtime orchestration layer that wires existing modules end to end.
- Update `lean/main.py` from benchmark shell to safe QuantConnect adapter.
- Add approved setup registry/export coverage for all implemented setup evaluators.
- Add deterministic integration tests from QC-like fixtures through setup, scoring, ranking, risk, order intent, notification event, and dashboard export.
- Add Object Store export producer and dashboard read-only fetch/cache parser using existing key allowlist.
- Update static safety tests from blanket "no universe/order calls" to "only approved paper-only, gate-protected calls."

## Out Of Scope

- Real-money broker adapters, real broker credentials, leverage, margin, shorting, options, futures, crypto, Forex, or hidden live-money switches.
- Dashboard order controls or Render-side portfolio authority.
- New strategy setups, new scoring weights, or arbitrary MTF tuning.
- Profitability claims, fake backtests, fake portfolio values, or synthetic performance evidence.
- Replacing QuantConnect portfolio/order/fill state with local JSON, SQLite, CSV, GitHub, or Render state.
- Making Telegram delivery required for safety.

## Verification Strategy

Recommended targeted tests:

- `tests/test_runtime_orchestrator.py`: deterministic fixture proves setup -> score -> rank -> risk -> order intent -> event -> dashboard export.
- `tests/test_lean_runtime_bridge_static.py`: `lean/main.py` imports only approved MarketPilot modules, contains no real broker config, no credentials, no margin/leverage/shorting, and only gate-protected Paper execution.
- `tests/test_runtime_reconciliation_gate.py`: QC mismatch blocks new entries and preserves exits.
- `tests/test_dashboard_object_store_source.py`: Object Store payloads parse into `DashboardSnapshot`; missing/stale/malformed payloads degrade safely.
- `tests/test_runtime_notification_isolation.py`: Telegram delivery failure does not change order/risk/recovery decisions.
- Extend `tests/test_lean_static_safety.py` because it currently forbids all universe/order calls; Phase 10.1 needs a more precise safety policy.

External QuantConnect Cloud sync/live/Object Store/API checks should remain operator-run and recorded as `not_run` unless real credentials and services are configured outside repository files and chat artifacts.

## Safety Constraints

- QuantConnect remains authoritative for cash, equity, holdings, orders, fills, deployment status, algorithm status, Paper performance, and backtest results.
- Any new order path must be QuantConnect Paper only, gate-protected, idempotent, and impossible to redirect to a real broker by config.
- Render dashboard remains read-only.
- Telegram delivery success/failure cannot alter trading, exit, reconciliation, or recovery decisions.
- Signals use completed bars only; no incomplete bars, future bars, current-bar leakage, or same-bar fill assumptions.

## Anti-Patterns

- Putting strategy logic directly in `lean/main.py`.
- Using built-in EqualWeighting-style allocation as a shortcut; project risk sizing remains authoritative.
- Treating local JSON/dashboard cache as portfolio authority.
- Adding broad Cloud API clients before endpoint allowlists and secret redaction exist.
- Marking requirements complete based only on module tests when the E2E runtime path was not executed.
