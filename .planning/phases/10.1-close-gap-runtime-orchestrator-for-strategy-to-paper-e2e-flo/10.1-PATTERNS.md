## Runtime Orchestrator Pattern

The orchestrator should use frozen dataclasses and typed enums. It should accept pre-adapted domain objects and return a complete result, not mutate external state directly.

Recommended result shape:

```python
@dataclass(frozen=True)
class RuntimeOrchestrationResult:
    status: RuntimeOrchestrationStatus
    ranked_candidates: tuple[RankedCandidate, ...]
    risk_decisions: tuple[RiskDecision, ...]
    order_intents: tuple[OrderIntent, ...]
    notification_events: tuple[NotificationDomainEvent, ...]
    skipped_reasons: tuple[str, ...]
    evidence: Mapping[str, object]
```

Candidate flow:

```text
SetupResult -> score_setup_result -> rank_candidates -> evaluate_portfolio_risk -> OrderIntent
```

Gate flow:

```text
ValidationGateDecision -> evaluate_paper_mode -> reconciliation gate -> risk gate -> paper-only intent
```

## LEAN Bridge Pattern

- Keep LEAN object access at the edge.
- Convert LEAN symbols/bars/portfolio into MarketPilot typed inputs.
- Follow `quantconnect_paper.py`: explicit statuses, no fake execution.
- Follow `test_lean_static_safety.py`: forbidden calls remain forbidden unless a plan explicitly narrows and tests a paper-only allowed subset.
- Do not put strategy logic directly in `lean/main.py`.

## Dashboard Export Pattern

- Use `dashboard/data.py` as the closest analog.
- Export only from QuantConnect-authoritative snapshots.
- Use approved Object Store keys already defined in `OBJECT_STORE_EXPORT_KEYS`.
- Missing source should produce degraded metadata, not fake sections.
- Keep `dashboard/config.py` read-only constraints intact.

## Specific Integration Risks

- `lean/main.py` safety tests currently forbid `AddUniverse` and all order calls. Phase 10.1 must update the safety policy deliberately.
- `marketpilot/setups/__init__.py` exports only Relative Strength; setup registry work must cover Trend Pullback and Volume Breakout too.
- Scoring requires explicit later gates for `BUY_CANDIDATE`; high scores are not order instructions.
- Portfolio state must come from QuantConnect, not dashboard JSON/local files.
- Telegram transport failures must be isolated.
- Dashboard currently supports `none` and `local_json`; Object Store/API support must preserve read-only endpoint allowlists and no secret-like paths.
- `not_run` is acceptable external evidence; Phase 10.1 must not fake QC deployment/backtest/paper artifacts.
- Risk sizing must remain Decimal-based.
- Idempotency keys must use `make_order_idempotency_key`.
- LEAN bridge must not invent QuantConnect APIs.
