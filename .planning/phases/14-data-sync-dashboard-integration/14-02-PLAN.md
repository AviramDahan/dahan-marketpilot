<objective>
Extend the dashboard data layer to support the `sync_jsonl` data source kind with three-state freshness evaluation. Add the ERROR member to the freshness enum and implement a loader that reads the last JSONL line from the sync file, evaluates freshness from source_timestamp age, and returns an honest DashboardSnapshot (degraded state for missing data per D-14, D-04).

Purpose: The dashboard needs to display QC portfolio data with freshness guarantees. This plan creates the data loading path that Plan 03 (display) will consume. The loader reads from the JSONL file that Plan 01's sync module writes — the file is the interface boundary (no import of marketpilot.sync needed per Pitfall 6).

Output: Extended `dashboard/models.py` and `dashboard/data.py` with sync_jsonl support.
</objective>

  <action>
Extend `dashboard/data.py` with a `sync_jsonl` data source loader:

1. **Add dispatch branch** in `load_dashboard_snapshot()` — after the `"object_store"` check, add:
   ```
   if config.data_source_kind == "sync_jsonl":
       return _load_sync_jsonl_snapshot(config.data_source_path, config=config, cache_timestamp=now)
   ```

2. **Create `_load_sync_jsonl_snapshot(path_value: str | None, *, config: DashboardConfig, cache_timestamp: datetime) -> DashboardSnapshot`** following the exact pattern of `_load_local_json_snapshot`:
   - If `path_value` is None/empty → return `DashboardDataClient.not_configured(missing=("dashboard_data_source",))`
   - If file doesn't exist or is empty → return `_source_error(code="sync_no_data", message="No sync data available — run python -m marketpilot sync to start", reason="no_sync_data", status=DashboardSectionStatus.NOT_AVAILABLE)`
   - Read last line using seek-from-end pattern (seek to end, read last 4096 bytes, split newlines, parse last non-empty line with json.loads)
   - On parse error → return `_source_error(code="sync_parse_error", ...)`

3. **Apply 3-state freshness** to the parsed record:
   - Extract `source_timestamp` from record, parse ISO-8601 with `datetime.fromisoformat()`
   - Calculate `age_seconds = (cache_timestamp - source_timestamp).total_seconds()`
   - Use `config.stale_warning_seconds` (600) and `config.stale_error_seconds` (1800) as thresholds:
     - age ≤ stale_warning_seconds → `DashboardFreshnessStatus.FRESH`
     - stale_warning_seconds < age ≤ stale_error_seconds → `DashboardFreshnessStatus.STALE`
     - age > stale_error_seconds → `DashboardFreshnessStatus.ERROR`
   - If `source_timestamp` missing or unparseable → `DashboardFreshnessStatus.UNKNOWN`

4. **Check generation counter** — per D-05: read `generation` field from record. This is informational for now (the dashboard doesn't track expected generation — that would require state). Log warning if generation is 0 or missing.

5. **Build DashboardSnapshot** from the parsed JSONL record:
   - Map `record["portfolio"]["holdings"]` to portfolio items
   - Set `DashboardSourceMetadata` with `source="quantconnect_sync_jsonl"`, `source_timestamp`, `cache_timestamp`, `freshness_status`, `authority=DashboardAuthority.AUTHORITATIVE`
   - Build `DashboardPortfolioSection` with status AVAILABLE (or STALE/ERROR matching freshness for section-level status)
   - Use `DashboardDataClient.from_quantconnect_portfolio_fixture()` if the existing method can accept the JSONL record format, OR build manually following its pattern

Key constraint: This function does NOT import from `marketpilot.sync` or `marketpilot.qc_api`. The JSONL file is the interface boundary (Pitfall 6). Only stdlib `json`, `pathlib`, `datetime` used for reading.

All datetime comparisons use UTC-aware datetimes per SAFE-04.
  </action>
