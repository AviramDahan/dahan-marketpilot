# Phase 16 Plan 03: Durable Lock, Run Ledger, Idempotency, And Catch-Up

## Objective

Plan the lock and audit state layer that prevents overlapping scheduler cycles, records run history, and supports conservative retries/catch-up.

## Context

@.planning/phases/16-production-scheduler/16-CONTEXT.md
@.planning/phases/16-production-scheduler/16-PATTERNS.md
@marketpilot/sync.py
@marketpilot/dashboard_export.py

## Tasks

### Task 1: Define lock and storage interfaces

Planned files: `marketpilot/scheduler_lock.py`, `marketpilot/scheduler_storage.py`, `tests/test_scheduler_lock.py`

- Define `LockStore` with acquire, renew, release, inspect, owner, run id, lease start, and lease expiration fields.
- Define `SchedulerStorage` for append-only run/job/heartbeat/system-health records.
- Provide a local JSONL/file adapter for deterministic Phase 16 tests and local operation.
- Keep the interface ready for Phase 16.1 shared durable storage without introducing that production backend now.

### Task 2: Implement idempotency and catch-up contracts

Planned files: `marketpilot/scheduler_storage.py`, `tests/test_scheduler_storage.py`

- Define stable idempotency keys for run, job, signal, order-intent, order-read, dashboard export, and notification records.
- Reuse ids on retry; never generate a second order-intent for the same eligible cycle.
- Record missed cycles and catch-up decisions.
- Skip order creation when data is stale or the market window is no longer valid.

- `python -m pytest tests/test_production_runner.py tests/test_scheduler_jobs.py -q`
- `python -m pytest -q`

## Success Criteria

- Overlapping runs are rejected or skipped with an auditable reason.
- Expired leases are recoverable without duplicate unsafe actions.
- Catch-up records missed work but does not backfill unsafe orders.
- JSONL audit state remains append-only and QuantConnect remains authoritative.
