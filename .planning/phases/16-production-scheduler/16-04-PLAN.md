# Phase 16 Plan 04: Heartbeat, System Health, And Missed-Run Monitoring

## Objective

Plan scheduler heartbeat records, system-health exports, and a GitHub Actions monitor that detects missed worker runs without executing the trading pipeline.

## Context

@.planning/phases/16-production-scheduler/16-CONTEXT.md
@.planning/phases/16-production-scheduler/16-RESEARCH.md
@marketpilot/notification_events.py
@marketpilot/dashboard_export.py

## Tasks

### Task 1: Add heartbeat and system-health record contracts

Planned files: `marketpilot/scheduler_health.py`, `tests/test_scheduler_health.py`

- Define heartbeat status, last successful run, last attempted run, missed-run count, error summary, and dependency-health fields.
- Emit health records from the scheduler without relying on the dashboard being deployed.
- Keep health records JSON-compatible for Phase 16.1 dashboard and Telegram integrations.

### Task 2: Add monitor-only GitHub Actions workflow

Planned files: `scripts/check_scheduler_heartbeat.py`, `.github/workflows/marketpilot-heartbeat-monitor.yml`, `tests/test_scheduler_health.py`

- Create a heartbeat checker that reads the latest health record and exits nonzero when freshness thresholds are breached.
- Configure a GitHub Actions scheduled workflow for monitoring only.
- Ensure the workflow cannot run scans, signals, QC commands, or order paths.
- Route alert output through safe notification/system-health paths where available.

## Verification

- `python -m pytest tests/test_scheduler_health.py -q`
- `python scripts/check_scheduler_heartbeat.py --help`
- `python -m pytest -q`

## Success Criteria

- Worker freshness can be audited independently of the dashboard UI.
- Missed scheduler runs can be detected while the local computer is off.
- GitHub Actions remains strictly monitor-only.
- Monitor failures do not create or modify orders.
