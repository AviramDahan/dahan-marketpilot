# Phase 16 Plan 02: Production Runtime Runner And Job Graph

## Objective

Define one production runtime runner that executes a single self-contained paper-trading cycle through dependency-aware jobs.

## Context

@.planning/phases/16-production-scheduler/16-CONTEXT.md
@.planning/phases/16-production-scheduler/16-PATTERNS.md
@marketpilot/runtime_orchestrator.py
@marketpilot/sync.py
@marketpilot/qc_api.py
@marketpilot/dashboard_export.py
@marketpilot/notification_events.py

## Tasks

### Task 1: Create typed job result contracts

Planned files: `marketpilot/scheduler_jobs.py`, `tests/test_scheduler_jobs.py`

- Define job ids, job states, dependency results, skip reasons, durations, and correlation metadata.
- Model the planned graph: market guard -> QuantConnect sync/reconciliation -> runtime evaluation -> paper delivery gate -> order/fill polling -> dashboard export -> notification emission -> heartbeat.
- Ensure failed or skipped upstream jobs prevent unsafe downstream jobs from running.

### Task 2: Create the single-cycle production runner

Planned files: `marketpilot/production_runner.py`, `tests/test_production_runner.py`

- Compose existing sync, runtime orchestration, QuantConnect, dashboard export, and notification boundaries.
- Preserve existing `PAPER_TRADING_ONLY`, paper deployment, and no-real-money protections.
- Emit one run manifest with stable run id, job outcomes, skip reasons, and timing data.
- Never place or infer real orders outside the existing paper-gated paths.

## Success Criteria

- A single function can run one complete paper workflow cycle with dependency-aware outcomes.
- Downstream jobs are skipped when prerequisites fail.
- Existing strategy and safety logic remain authoritative and are not duplicated.
- Runner outputs are JSON-compatible for later dashboard/system-health exports.
