# Phase 16.3 Plan 06: Telegram Simulation Alerts and Daily Summary

## Objective

Add simulation-labeled Telegram notifications for scanner candidates, simulated entries/exits, stop/target events, daily summaries, and system issues.

## Tasks

### Task 1: Add simulation notification builders

Planned files: `marketpilot/simulation_notifications.py`, `marketpilot/notification_events.py`

- Build events for top candidate detected.
- Build events for simulated entry opened.
- Build events for simulated stop hit, target hit, and trade closed.
- Build daily summary event from simulation performance.
- Include correlation id and simulation labels.

### Task 2: Preserve delivery isolation

Planned files: `marketpilot/telegram.py`, `tests/test_simulation_notifications.py`

- Ensure delivery success/failure does not control scanner, simulator, risk, or dashboard state.
- Redact secret-like fields.
- Avoid financial-advice and guaranteed-profit language.

### Task 3: Expand alert coverage tests

Planned files: `tests/test_simulation_notifications.py`, `tests/test_telegram_alert_coverage.py`

- Test all required simulation alert families.
- Test duplicate suppression/rate limiting where existing infrastructure applies.
- Test Telegram failure isolation.

## Verification

- `python -m pytest tests/test_simulation_notifications.py tests/test_telegram_alert_coverage.py tests/test_telegram_failure_isolation.py tests/test_telegram_safety.py -q`

## Success Criteria

- Telegram can report simulation activity clearly.
- Delivery remains non-authoritative.
- Messages cannot be mistaken for real-money trade instructions.
