# Phase 16.3 Plan 03: Scanner Engine Over Existing Setup Evaluators

## Objective

Build the autonomous scanner path that evaluates all eligible symbols with existing setup evaluators, scores candidates, ranks them, and records rejected candidates.

## Tasks

### Task 1: Add scanner contracts

Planned files: `marketpilot/scanner.py`

- Define scan input, per-symbol result, accepted candidate, rejected candidate, and scan result dataclasses.
- Carry one correlation id for the scan cycle.
- Include timestamp, strategy mode, setup name, evidence, score, rank, and rejection reasons.

### Task 2: Reuse existing setup/scoring/ranking modules

Planned files: `marketpilot/scanner.py`, `marketpilot/runtime_orchestrator.py`

- Use `get_default_setup_registry`.
- Run Trend Pullback, Volume Breakout, and Relative Strength Leader without duplicating strategy rules.
- Score valid setup results with `score_setup_result`.
- Rank candidates with `rank_candidates`.
- Preserve rejected setup reasons.

### Task 3: Add scanner tests

Planned files: `tests/test_scanner.py`, `tests/test_runtime_orchestrator.py`

- Test all three strategies are invoked for eligible symbols.
- Test rejected universe symbols do not reach setup evaluation.
- Test valid candidates are ranked deterministically.
- Test rejected setup candidates remain visible with reasons.
- Test no order intent or simulator trade is created in scanner-only output.

## Verification

- `python -m pytest tests/test_scanner.py tests/test_runtime_orchestrator.py tests/test_trend_pullback_contract.py tests/test_volume_breakout_contract.py tests/test_relative_strength_contract.py tests/test_ranking.py -q`

## Success Criteria

- Scanner produces auditable candidates and rejections.
- Strategy logic is reused, not forked.
- No QC or broker path is required.
