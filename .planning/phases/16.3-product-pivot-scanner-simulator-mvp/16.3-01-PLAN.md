# Phase 16.3 Plan 01: Product Mode Contracts and Safety Fences

## Objective

Define explicit product modes and safety boundaries so `simulation_only` becomes the core MVP path while existing QuantConnect work remains parked for optional future validation.

## Tasks

### Task 1: Add product mode contracts

Planned files: `marketpilot/product_modes.py`, `tests/test_product_modes.py`

- Define `ProductMode` values: `simulation_only`, `qc_paper_validation`, `qc_native_algorithm`.
- Add mode capability metadata: requires_qc, allows_broker, allows_real_orders, dashboard_mutation_allowed, implemented_now.
- Make `simulation_only` the only implemented Phase 16.3 mode.
- Ensure `qc_paper_validation` is parked and `qc_native_algorithm` is future-only.

### Task 2: Add safety assertions

Planned files: `marketpilot/product_modes.py`, `tests/test_simulation_mode_safety.py`

- Assert `simulation_only` rejects QuantConnect credentials as required dependencies.
- Assert no live brokerage credentials or real-order flags are accepted.
- Assert dashboard mutation/order controls are false.
- Preserve existing `PAPER_TRADING_ONLY` checks.

### Task 3: Document the pivot

Planned files: `docs/simulation_mode.md`

- Explain the three product modes.
- State that Phase 16.2 is parked QC validation, not deleted.
- State `simulation_only` is internal simulation, not financial advice, not real trading, and not QuantConnect Paper execution.

## Verification

- `python -m pytest tests/test_product_modes.py tests/test_simulation_mode_safety.py -q`
- Secret/wording review for broker, live-money, and guaranteed-profit language.

## Success Criteria

- `simulation_only` is explicit, test-covered, and independent of QuantConnect.
- QC modules remain available but not required for simulator MVP.
- Safety documentation is clear enough for a future agent to avoid re-centering QC accidentally.
