# Phase 16.3 Research: Scanner Simulator MVP

## Codebase Findings

The codebase already contains most of the strategy, scoring, risk, notification, dashboard, scheduler, and audit primitives needed for a simulator MVP.

### Strong Reuse Candidates

- `marketpilot.universe.build_universe_snapshot` already normalizes and rejects universe candidates with explicit issues.
- `marketpilot.data_quality.UniverseCandidate`, `UniverseDecision`, and `UniverseSnapshot` already provide accepted/rejected symbol contracts.
- `marketpilot.runtime_orchestrator.get_default_setup_registry` already names the three approved setup evaluators.
- `marketpilot.scoring.score_setup_result` and `marketpilot.ranking.rank_candidates` already create scored and ranked candidates.
- `marketpilot.risk.evaluate_portfolio_risk` already calculates quantity and rejects unsafe candidates from a `PortfolioSnapshot`.
- `marketpilot.audit_journal.AppendOnlyJsonlAuditJournal` already provides an append-only persistence pattern.
- `dashboard.models.DashboardSnapshot` already includes portfolio, positions, trades, signals, strategies, risk, notifications, activity, and system sections.
- `marketpilot.notification_events` already includes alert families for candidate/order/lifecycle/stop/target/daily summary style notifications.
- Scheduler, durable lock, heartbeat, and Render shared state already exist from Phases 16 and 16.1.

### Main Gap

The runtime path currently treats QuantConnect as the authority before producing executable Paper flow. Phase 16.3 needs a parallel `simulation_only` path where the internal simulator is authoritative for simulated positions and P&L.

### Design Direction

Add narrow modules rather than rewriting:

- `marketpilot/product_modes.py` or equivalent mode contract.
- `marketpilot/scanner.py` for universe -> setup -> scoring -> ranking.
- `marketpilot/internal_paper_simulator.py` for simulated portfolio/trade lifecycle.
- `marketpilot/simulation_reports.py` for performance and evidence outputs.
- Dashboard export extensions for simulation sections.

QuantConnect modules remain intact and parked for `qc_paper_validation`.

## Risks

- Existing names like "Paper Trading" can confuse internal simulation with QC Paper execution. Labels must be explicit.
- Simulator persistence needs restart-safe append-only records without becoming a hidden real-money ledger.
- Dashboard must stay read-only and avoid any order-control affordance.
- Telegram wording must avoid financial advice and guaranteed-profit claims.
- Scanner inputs need deterministic fixtures first; live market data ingestion can be staged if provider access is not already reliable.

## Recommended Plan Shape

Seven plans across four waves:

1. Product mode contracts and safety fences.
2. Universe builder.
3. Scanner engine.
4. Internal paper simulator.
5. Dashboard simulation MVP.
6. Telegram simulation alerts.
7. Evidence, reports, docs, and acceptance gate.
