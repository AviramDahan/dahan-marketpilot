# Phase 16.3 Context: Product Pivot - Scanner Simulator MVP

## Operator Decision

The operator approved a product pivot on 2026-06-19. The near-term product goal is no longer primarily QuantConnect Paper Trading authority. The new near-term MVP is:

`Autonomous Stock Scanner + Internal Paper Simulator`

QuantConnect work must be preserved, but Phase 16.2 is parked as optional `qc_paper_validation` and must not block the simulator MVP.

## Target Architecture

```text
Stock Universe
  -> Scanner
  -> Strategy Setups
  -> Scoring + Ranking
  -> Risk / Position Sizing
  -> Internal Paper Simulator
  -> Dashboard
  -> Telegram
  -> Reports / Performance Analytics
```

## Product Modes

- `simulation_only`: core Phase 16.3 MVP. No QuantConnect credentials, deploy id, `/live/orders/read`, broker credentials, or real order authority required.
- `qc_paper_validation`: parked optional mode. Existing QC Paper infrastructure may later validate scanner signals externally.
- `qc_native_algorithm`: future-only mode. QC/LEAN chooses and executes inside QuantConnect; not part of Phase 16.3.

## Reusable Components

- Universe/data quality: `marketpilot/universe.py`, `marketpilot/data_quality.py`
- Setup evaluators: `marketpilot/setups/trend_pullback.py`, `marketpilot/setups/volume_breakout.py`, `marketpilot/setups/relative_strength.py`
- Scoring/ranking: `marketpilot/scoring.py`, `marketpilot/ranking.py`
- Risk/position sizing: `marketpilot/risk.py`
- Scheduler/worker: `marketpilot/scheduler_*`, `marketpilot/production_runner.py`
- Dashboard contracts/views: `dashboard/models.py`, `dashboard/pages/*`, `marketpilot/dashboard_export.py`
- Telegram pipeline: `marketpilot/notification_events.py`, `marketpilot/telegram.py`
- Audit patterns: `marketpilot/audit_journal.py`, JSONL append-only ledgers

## Decisions

- D-01: Phase 16.3 implements `simulation_only` only; it must not depend on QuantConnect API credentials or live deployment ids.
- D-02: Phase 16.2 remains open and parked as optional QC validation; do not delete QC modules or mark 16.2 complete.
- D-03: Existing strategy setup evaluators must be reused; no new strategies are added during the pivot.
- D-04: Scanner output must preserve accepted and rejected symbols with reasons, setup evidence, score, rank, timestamp, and correlation id.
- D-05: Internal paper simulator is the authority for simulated trades and P&L in `simulation_only`.
- D-06: Simulator trades must never become real orders, QuantConnect orders, or broker orders.
- D-07: Dashboard remains read-only and must clearly label internal simulation mode.
- D-08: Telegram alerts are simulation-labeled and never control safety, scanner, simulator, or risk decisions.
- D-09: Every simulated trade requires traceable setup evidence, risk decision, entry, stop, target, quantity, lifecycle, exit reason, and P&L.
- D-10: Evidence report must prove no real orders, no QC dependency, no broker path, no secrets, and no guaranteed-profit claims.

## Scope

In scope:

- Product mode contracts.
- Universe builder formalization.
- Scanner engine across existing setup evaluators.
- Internal paper simulator with open/closed positions and P&L.
- Dashboard data/export and read-only views for simulation.
- Telegram simulation alerts and daily summary.
- Evidence report and documentation.

Out of scope:

- Real-money trading.
- Live brokerage integration.
- QuantConnect execution as a Phase 16.3 blocker.
- New strategies.
- Dashboard order controls.
- Claims of guaranteed profitability.
- Phase 17 or v1.2 work.
