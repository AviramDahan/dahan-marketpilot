# Phase 16.3 Plan 05: Dashboard Simulation MVP Export and Views

## Objective

Expose scanner and internal simulator state on the deployed read-only dashboard with clear simulation labels.

## Tasks

### Task 1: Extend dashboard snapshot data

Planned files: `marketpilot/dashboard_export.py`, `dashboard/models.py`, `dashboard/data.py`

- Add simulation source metadata.
- Include candidates, rejections, open simulated trades, closed simulated trades, simulated portfolio, performance, risk, activity, and system sections.
- Preserve existing QC dashboard loaders.
- Never expose secrets, raw credentials, or order controls.

### Task 2: Render simulation views

Planned files: `dashboard/pages/overview.py`, `dashboard/pages/signals.py`, `dashboard/pages/positions.py`, `dashboard/pages/trades.py`, `dashboard/pages/risk.py`

- Show top candidates today.
- Show rejected candidates and reasons.
- Show open simulated trades and closed simulated trades.
- Show win rate, average gain/loss, total simulated P&L, strategy breakdown, and portfolio simulation value.
- Label all sections as internal simulation mode.

### Task 3: Add dashboard tests

Planned files: `tests/test_dashboard_simulation_source.py`, `tests/test_dashboard_app_rendering.py`

- Test read-only rendering.
- Test no order buttons or mutation controls.
- Test simulation labels.
- Test stale/missing simulation data states.

## Verification

- `python -m pytest tests/test_dashboard_simulation_source.py tests/test_dashboard_app_rendering.py tests/test_dashboard_read_only.py tests/test_dashboard_pages.py -q`

## Success Criteria

- Dashboard becomes useful for scanner simulator monitoring.
- It is obvious this is internal simulation, not real trading or QC authority.
- Read-only safety remains intact.
