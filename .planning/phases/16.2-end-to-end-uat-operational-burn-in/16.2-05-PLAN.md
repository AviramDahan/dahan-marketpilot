## Tasks

### Task 1: Observe consecutive market sessions

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Capture at least two consecutive valid US market sessions.
- Extend to a third session if a holiday, early close, sparse signal, Render outage, or provider limitation leaves evidence weak.
- Require each counted session to show Render worker/dashboard, QuantConnect Paper deployment, shared state, and Telegram path observability.

### Task 2: Finalize UAT status

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-VERIFICATION.md`

- Mark each UAT row passed only when evidence exists.
- Use `blocked_external_not_verified`, `failed`, `skipped`, or `not_run` for anything unresolved.
- Include exact next action for every unresolved item.
- Do not close Phase 16.2 if UAT-01 through UAT-09 and OPS-01 are not all passed or intentionally escalated with explicit user approval.

### Task 3: Write final operational-readiness report

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-OPERATIONAL-READINESS.md`

- Summarize deployed service status, evidence chain, burn-in sessions, failure handling, recovery, cleanup, and residual risks.
- Confirm no local-computer dependency for the deployed runtime.
- Confirm Paper Trading only, QuantConnect authority, read-only dashboard, and Telegram non-authority.
- Avoid all profitability and real-money claims.

### Task 4: Update milestone status only if gates pass

Planned files: `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`

- If and only if all Phase 16.2 requirements pass, mark UAT-01 through UAT-09 and OPS-01 complete.
- Update ROADMAP Phase 16.2 plans and v1.1 completion gate.
- Update STATE with the final status and next eligible phase.
- If any required row remains unresolved, keep v1.1 active and report the blocker instead.
