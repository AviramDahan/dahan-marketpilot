# Phase 16.2 Plan 02: Deployed Session Observation

## Objective

Add and run a read-only deployed-session observer that records Render worker heartbeat, shared-state freshness, dashboard health, stale-data status, and monitor-only missed-run evidence for real market-session burn-in.

## Tasks

### Task 1: Build the deployed-session observer

Planned files: `scripts/phase16_2_observe_deployed_session.py`, `tests/test_phase16_2_observe_deployed_session.py`

- Reuse existing Render go-live and heartbeat checks where possible.
- Read dashboard URL/shared-state configuration from environment without logging secrets.
- Emit sanitized JSON with heartbeat age, dashboard HTTP status, shared-state source/freshness, paper-only flag, and local-computer independence evidence.
- Classify output as `passed`, `failed`, `blocked_external_not_verified`, or `not_run`.

### Task 2: Record first valid session evidence

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Run the observer during a valid US market session.
- Update UAT-02 for heartbeat and missed-run monitoring only if evidence is external and current.
- Update UAT-05 only if stale-data handling is actually observed or safely induced and restored.
- Add the session as burn-in candidate 1 for UAT-08 only if all required deployed surfaces are observable.

### Task 3: Preserve monitor-only boundaries

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Record that GitHub Actions monitoring does not run scans, orders, scheduler cycles, or QuantConnect commands.
- If missed-run evidence is simulated, label it as simulation and keep production missed-run external proof separate.

## Verification

## Success Criteria

- One valid session observation is captured without mutating trading state.
- Heartbeat, dashboard, shared state, stale/freshness, and monitor boundaries are visible.
- Evidence does not depend on the local computer being the scheduler runtime.
