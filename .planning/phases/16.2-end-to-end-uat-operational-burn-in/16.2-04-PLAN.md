## Tasks

### Task 1: Add a resilience check harness

Planned files: `scripts/phase16_2_resilience_checks.py`, `tests/test_phase16_2_resilience_checks.py`

- Provide subcommands for duplicate lock, stale data, fake QuantConnect failure, fake Telegram failure, and restored-state checks.
- Use fakes or isolated shared-state keys for local safety where provider mutation would be risky.
- Preserve Paper Trading only and avoid order placement unless delegated to the already gated Paper smoke.
- Emit sanitized JSON and explicit cleanup instructions/status.

### Task 2: Verify duplicate-run prevention

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Run a controlled duplicate invocation or same-lock harness against the durable lock contract.
- Prove the second run is skipped/rejected before duplicate Paper order work.
- Record UAT-04 only if the durable lock path is exercised.

### Task 3: Verify restart/redeploy recovery

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Trigger or observe a controlled Render worker restart/redeploy.
- Confirm subsequent heartbeat, shared-state freshness, dashboard availability, and Telegram path recovery.
- Record before/after timestamps and restored state.

### Task 4: Verify temporary external failures

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Use fake QuantConnect client failure or read-only provider error evidence for UAT-06.
- Use fake Telegram transport or controlled bad delivery target for UAT-07, then restore production Telegram config.
- Prove safety decisions and Paper Trading operation do not depend on Telegram delivery success.
