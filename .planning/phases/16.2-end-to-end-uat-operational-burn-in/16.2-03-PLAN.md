## Tasks

### Task 1: Add an E2E trace summarizer

Planned files: `scripts/phase16_2_trace_e2e_flow.py`, `tests/test_phase16_2_trace_e2e_flow.py`

- Normalize evidence from production run result, QuantConnect order read output, shared-state dashboard payload, dashboard activity, and Telegram runtime delivery result.
- Require correlation identifiers or tags that connect the flow across stages.
- Mark flow status incomplete if any required segment is missing or only locally mocked.
- Redact credentials, tokens, chat IDs, and deploy identifiers from all output.

### Task 2: Prefer natural deployed runtime evidence

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Observe the Render worker's real market-session runtime output first.
- If a natural eligible Paper order appears, poll QuantConnect order authority and connect it to dashboard/shared-state/Telegram evidence.
- If the strategy produces no trade, record the no-trade decision as partial flow evidence but do not mark UAT-01 passed unless the Paper order path is proven by an eligible order or explicit probe.

### Task 3: Run the explicit Paper-only probe if needed

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Use `scripts/qc_object_store_signal_smoke.py` only with explicit operator gating and Paper-only safety enabled.
- Label the evidence as `operator_gated_paper_probe`, not strategy-generated production signal.
- Poll `/live/orders/read` or the existing wrapper until a tagged Submitted/Filled/Rejected order result is observed or the window expires.
- Confirm sync/shared-state/dashboard/Telegram surfaces reflect the runtime after the probe, or keep those segments pending.
- Stop or restore any temporary deployment/probe state according to script safety options.
