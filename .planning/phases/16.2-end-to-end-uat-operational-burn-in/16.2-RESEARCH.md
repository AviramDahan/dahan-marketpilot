# Phase 16.2 Research: End-to-End UAT & Operational Burn-in

**Researched:** 2026-06-17
**Mode:** Local artifact and codebase research
**Status:** Complete

## Research Scope

Phase 16.2 is not a feature-expansion phase. The research question is how to
prove the already deployed Render + QuantConnect + Telegram Paper Trading
product is operational under real conditions without fabricating provider
evidence, weakening paper-only safety, or adding new strategy scope.

## Existing Assets To Reuse

- `scripts/verify_render_golive.py` already performs read-only Render dashboard
  and shared-state checks with sanitized JSON output.
- `scripts/check_scheduler_heartbeat.py` already evaluates scheduler heartbeat
  freshness and supports monitor-only missed-run checks.
- `scripts/telegram_runtime_smoke.py` already verifies production runtime
  notification delivery without letting Telegram control safety logic.
- `scripts/qc_object_store_signal_smoke.py` already provides the operator-gated
  Paper-only probe for tagged QuantConnect order authority through Object Store
  delivery.
- `marketpilot/shared_state.py` already provides Render Key Value dashboard
  mirror state, activity records, and durable lock behavior.
- `marketpilot/production_runner.py` and `marketpilot/scheduler_jobs.py` already
  provide production cycle and dependency-aware job boundaries.
- `dashboard/app.py` and `dashboard/data.py` already expose password-protected
  dashboard state with source, freshness, and paper-only metadata.

## Verification Strategy

The burn-in should be split into independent proof tracks:

1. Prepare sanitized evidence ledger and UAT report files.
2. Observe deployed heartbeat, shared state, dashboard, and Telegram during a
   valid market session.
3. Prove one authoritative Paper order/fill/rejection chain through
   QuantConnect, either from a natural strategy signal or from the existing
   explicitly labeled Object Store Paper smoke probe.
4. Prove recovery and failure behavior through reversible tests that do not
   damage the active Paper deployment.
5. Run at least two consecutive valid US market sessions and close v1.1 only if
   all UAT rows have real evidence.

## Evidence Rules

- QuantConnect remains authority for orders, fills, rejections, deployment
  state, cash, holdings, and algorithm status.
- Render shared state and dashboard are mirrors only.
- Telegram delivery is observational and never safety-controlling.
- Local deterministic tests can support confidence but cannot replace external
  UAT evidence.
- External rows must remain `not_run` or `blocked_external_not_verified` until
  observed against the deployed product.
- No raw provider credentials, account passwords, tokens, deploy hooks, chat IDs,
  or dashboard passwords may be committed or pasted into evidence files.

## Risk Notes

- Sparse strategy signals can delay UAT-01. The existing Object Store Paper
  smoke may be used only as an explicitly labeled operator-gated probe.
- Some failure modes should be proven with fake clients or controlled bad
  configuration rather than inducing provider outages.
- Restart/redeploy checks must include a restored-system observation.
- Missed-run monitoring must remain monitor-only and must not become a hidden
  scheduler.

## Research Complete

The implementation path is to add burn-in evidence scaffolding and scripts only
where needed, then use existing external verification helpers to gather real
evidence over market sessions.
