## Objective

Create the Phase 16.2 UAT ledger, burn-in evidence log, and operational-readiness report scaffold so every later external check has a consistent pass/fail/blocked/not-run destination.

## Tasks

### Task 1: Create UAT and burn-in evidence templates

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-UAT.md`, `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-BURN-IN-LEDGER.md`

- Add one row per requirement: UAT-01 through UAT-09 and OPS-01.
- Include status values `passed`, `failed`, `blocked_external_not_verified`, `skipped`, and `not_run`.
- Add evidence fields for provider, command/script, timestamp, sanitized result, cleanup state, and linked commit.
- Pre-fill Phase 15 and Phase 16.1 prior evidence as prerequisites, not as Phase 16.2 pass evidence.
- Mark every Phase 16.2 external UAT row as `not_run` at creation.

### Task 2: Add a sanitized report aggregator

Planned files: `scripts/phase16_2_evidence_report.py`, `tests/test_phase16_2_evidence_report.py`

- Parse the Phase 16.2 UAT and ledger files.
- Produce a sanitized JSON/Markdown status summary for the operator.
- Fail closed if any raw secret-like value appears in evidence text.
- Distinguish local deterministic evidence from deployed external evidence.
- Return non-zero until all Phase 16.2 mandatory rows are passed.

### Task 3: Create the operational-readiness report scaffold

Planned files: `.planning/phases/16.2-end-to-end-uat-operational-burn-in/16.2-OPERATIONAL-READINESS.md`

- Add sections for product boundary, deployed services, evidence summary, unresolved risks, cleanup, and final v1.1 decision.
- Explicitly state that the report cannot claim profitability, expected returns, real-money readiness, or live brokerage readiness.
- Leave final status as `not_run` until all execution waves are complete.

## Verification

- `python -m pytest tests/test_phase16_2_evidence_report.py -q`
- Run the evidence report script and confirm it returns incomplete/not-run before external evidence exists.
- Secret scan over Phase 16.2 planning and report files.

## Success Criteria

- Every Phase 16.2 requirement has a visible evidence row.
- The report scaffold cannot accidentally close v1.1 while required rows are missing.
- The evidence workflow preserves no-fake-evidence and no-secret rules.
