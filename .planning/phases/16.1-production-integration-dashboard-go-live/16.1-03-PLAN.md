# Phase 16.1 Plan 03: Dashboard Production Data Source And Auto-Refresh

## Objective

Connect the Streamlit dashboard to the shared production data source, add controlled auto-refresh, and preserve read-only degraded-state behavior.

## Context

@.planning/phases/16.1-production-integration-dashboard-go-live/16.1-CONTEXT.md
@dashboard/config.py
@dashboard/data.py
@dashboard/app.py
@dashboard/safety_view.py
@tests/test_dashboard_runtime_source.py
@tests/test_dashboard_read_only.py

## Tasks

### Task 1: Add shared-store dashboard source

Planned files: `dashboard/config.py`, `dashboard/data.py`, `tests/test_dashboard_runtime_source.py`

- Add a production dashboard source kind such as `shared_state`.
- Load portfolio, positions, trades/orders, fills, signals, notifications, activity, and system health from shared state.
- Show missing/stale/error states when records are missing, malformed, stale, or marked unhealthy.
- Keep QuantConnect-authoritative labels and fixture rejection behavior.

### Task 2: Enforce production no-`none` guard

Planned files: `dashboard/config.py`, `config/dashboard.yaml`, `tests/test_dashboard_runtime_source.py`

- Add a production environment guard so `MARKETPILOT_ENV=production` or equivalent rejects `data_source_kind=none`.
- Keep local/dev defaults safe and explicit.
- Ensure config safe dicts redact secrets and do not expose shared store URLs.

### Task 3: Add controlled auto-refresh

Planned files: `dashboard/app.py`, `dashboard/config.py`, `tests/test_dashboard_read_only.py`, `docs/dashboard.md`

- Add a controlled auto-refresh setting with conservative interval.
- Ensure manual refresh remains read-only.
- Ensure no auto-refresh hides stale/error banners or fetches data before authentication.

## Verification

- `python -m pytest tests/test_dashboard_runtime_source.py tests/test_dashboard_read_only.py tests/test_dashboard_auth.py tests/test_dashboard_pages.py -q`
- Static scan for forbidden dashboard actions.

## Success Criteria

- The deployed dashboard can read real production shared data.
- Production mode cannot silently run with no data source.
- Dashboard remains password-gated, read-only, and fail-visible.
