## Objective

Create safe opt-in verification scripts for Render dashboard URL/auth, worker heartbeat, shared data, Telegram runtime delivery, and local-computer independence.

## Tasks

### Task 1: Add Render go-live verifier

Planned files: `scripts/verify_render_golive.py`, `tests/test_render_golive_verification.py`

- Refuse to run unless an explicit enable env var is set.
- Check dashboard URL responds and remains password protected.
- Check shared state contains recent worker heartbeat and production data records.
- Check sanitized output only; never print dashboard password, Redis URL, QC token, Telegram token, or chat id.
- Record local-computer independence evidence instructions: verification should read Render-hosted outputs, not local files.

### Task 2: Add runtime Telegram smoke

Planned files: `scripts/telegram_runtime_smoke.py`, `tests/test_render_golive_verification.py`

- Send a system-health notification through the same production notification sink used by the runner.
- Refuse to run unless explicitly enabled.
- Persist or print only safe delivery result fields.
- Prove failure does not alter safety logic.

## Verification

- `python -m pytest tests/test_render_golive_verification.py tests/test_telegram.py tests/test_notification_safety.py -q`
- Dry-run commands for both scripts.
- Secret scan of script outputs and source.

## Success Criteria

- Operators have repeatable external checks for Phase 16.1 go-live.
- Checks are safe-by-default, explicit, and sanitized.
- External evidence can be copied into `16.1-VERIFICATION.md` without secrets.
