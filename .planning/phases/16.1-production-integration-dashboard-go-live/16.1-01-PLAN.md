# Phase 16.1 Plan 01: Shared Production State Store

## Objective

Create the shared state abstraction and Render Key Value adapter that both the scheduler worker and dashboard can use for production data.

## Tasks

### Task 1: Define shared-state contracts and fake adapter

Planned files: `marketpilot/shared_state.py`, `tests/test_shared_state.py`

- Define JSON-compatible records for dashboard sections, scheduler heartbeat, run status, notification results, and activity.
- Define a `SharedStateStore` interface with get/set JSON, append activity, latest heartbeat, and lock operations.
- Implement an in-memory fake adapter for deterministic tests.
- Ensure records carry source, authority, timestamp, freshness metadata, and `paper_trading_only`.

### Task 2: Add Render Key Value adapter boundary

Planned files: `pyproject.toml`, `requirements.txt`, `marketpilot/shared_state.py`, `tests/test_shared_state.py`

- Add a Redis-compatible Python client dependency for Render Key Value.
- Implement `RenderKeyValueStore.from_env()` using `REDIS_URL` without logging the URL.
- Store keys under a stable namespace such as `marketpilot:v1.1:*`.
- Add tests with a fake Redis client proving JSON serialization, no secret leakage, and lock/idempotency semantics.

## Verification

- `python -m pytest tests/test_shared_state.py -q`
- `python -m pytest tests/test_scheduler_storage.py tests/test_scheduler_health.py -q`
- Secret scan for `REDIS_URL`, token, password, and chat id values.

## Success Criteria

- Worker and dashboard can share JSON records through one interface.
- Redis/Valkey details do not leak into dashboard pages or runner orchestration.
- Shared storage remains a mirror and never replaces QuantConnect authority.
